# GrowBox — новая плата с европейской закупкой

**EU-0.1, 21.10.2026: плата разведена полностью (см. «Разводка 21.10.2026» и «Силовой контур LED2 и ключи LED» в [DESIGN.md](DESIGN.md)); силовой контур LED2 проложен вручную, ключи LED — TK22E10N1; добавлен монитор мощности INA226.** Открыть [PCB_EU.kicad_pro](PCB_EU.kicad_pro) в KiCad 10. Проект содержит схему и [PCB_EU.kicad_pcb](PCB_EU.kicad_pcb): 199 позиций схемы, 108 сверху / 91 снизу, четыре слоя меди; 1636 участков дорожек, 352 переходных, плоскость GND на In1.Cu и заливки GND на F.Cu/B.Cu. Неразведённых соединений нет; крепёж радиаторов и физическая сборка не подтверждены.

Сохраняются функции PCB_V1: два LED-канала с общей яркостью, два независимых PWM/тахоканала вентиляторов, PTC, помпа, SHT4x, поплавок, RTC с CR2032, microSD, Wi-Fi и существующие функции интерфейса/расписаний. Функциональное основание — `origin/main` `1d6b1eaf1273149b32eb1cf5c91fc69ff6a6ca09`.

**Старую прошивку на эту плату не устанавливать:** GPIO и микросхема RTC изменены. Например, прежний GPIO25 помпы теперь управляет LED. Новая прошивка пока не написана и не собрана.

## Проверки

Проверено **KiCad CLI 10.0.7**: ERC 0 ошибок/0 предупреждений; 53 проверки, 498 подключённых выводов. Исключений ERC в проекте нет; сохранены четыре стандартные отключённые категории KiCad, перечисленные в `validation.json`.

Для реального PCB: 23 466 проверок размещения; DRC со сверкой схемы — 0 геометрических нарушений, 0 расхождений и **0 неразведённых соединений**. PCB пересобран из `placement.json` и netlist через `build_board.py` + `route_power.py` + `route_board.py`; повторный запуск даёт тот же файл. Отдельно проверены 203 запланированных объекта меди (силовые контуры LED1 и LED2, ручные выводы LM3429, измерение мощности INA226) и 19 физически связанных групп. Проверены обе стороны, нумерация/цепи площадок, THT-маска, courtyards, запас вокруг паек на противоположной стороне, RF и предварительные механические резервы. Крепёж радиаторов, толщины меди, допустимые токи, температура и поведение преобразователя пока не подтверждены.

Целевая версия репозитория по `AGENTS.md` — **10.0.6**. Она здесь отсутствует; на этой версии результат пока не подтверждён. Обычная команда `hardware/check_all.py` ориентирована на старую PCB_V1 и в здешнем окружении остановилась из-за отсутствия `/usr/bin/kicad-cli`; лог — `review/baseline_check_all.txt`. Её успешное выполнение не заявляется.

Повторить проверки новой схемы с установленным KiCad 10.0.6:

```sh
python3 hardware/PCB_EU/tools/run_checks.py
```

Другую локальную версию разрешать явно, с записью фактической версии в результат:

```sh
python3 hardware/PCB_EU/tools/run_checks.py --kicad-cli /path/to/kicad-cli --allow-other-version
```

Схемы воспроизводятся без сторонних Python-пакетов:

```sh
python3 hardware/PCB_EU/tools/generate.py
```

Специальные посадки воспроизводятся командой `python3 hardware/PCB_EU/tools/generate_footprints.py`. Дополнительный DRC библиотечных образцов: `python3 hardware/PCB_EU/tools/check_footprint_drc.py --kicad-cli /path/to/kicad-cli`; нужен `pcbnew` той же версии в выбранном Python. Этот DRC не проверяет PCB изделия.

Проверка PCB требует Python с `pcbnew` той же версии; при необходимости указать `--kicad-python /path/to/python` или `KICAD_PYTHON`. `tools/build_board.py` воспроизводит неразведённый PCB из `placement.json` и экспортированного netlist, отказывается затирать дорожки/переходные/заливки. Для воспроизведения скопировать `PCB_EU.kicad_pro` во временный каталог с тем же базовым именем, использовать `--output /temporary/PCB_EU.kicad_pcb`, затем `tools/route_power.py --board /temporary/PCB_EU.kicad_pcb` и `tools/route_board.py --board /temporary/PCB_EU.kicad_pcb` (рядом также `PCB_EU.kicad_dru`). Последний добавляет план `routing.json`, сохраняет прочую медь и отказывается менять уже существующий объект с тем же UUID, если его геометрия отличается. Для DRC временной копии нужны проект и локальные библиотеки. Перед ручным изменением размещения сохранить координаты в JSON. `tools/plot_board.py --kicad-cli /path/to/kicad-cli` обновляет оба обзора (нужны PyMuPDF и Pillow).

Генератор схем перезаписывает схемы: после ручного редактирования сначала перенести изменения в генератор. ERC, связность и геометрический DRC не подтверждают устойчивость преобразователей, температуру, фактическую сборку с радиаторами или поведение прототипа.

## 3D-модели

Для всех **191 устанавливаемого компонента** назначены существующие локальные STEP-файлы. Контрольные площадки TP01–TP08 и четыре NPTH не изображают отдельные детали. В [libraries/EU.3dshapes](libraries/EU.3dshapes) находятся 16 собственных упрощённых моделей и 18 неизменённых моделей KiCad; 33 файла используются платой, ещё один — отдельный габарит радиатора. Внешние библиотеки моделей для просмотра этой PCB не требуются.

Открыть `PCB_EU.kicad_pro`, затем плату и 3D Viewer (`Alt+3`). Для C112 отдельно назначен корпус 10×20 мм; остальные электролиты 10 мм имеют корпус 10×16 мм. Снизу модели отражает сам KiCad. [Вид сверху](review/PCB_3D_front.png), [вид снизу](review/PCB_3D_back.png), [сборка STEP](review/PCB_EU_assembly.step).

**C508/C509/C510/C608/C609:** выбранный MPN `EEUFR1J101LB` имеет выводы с шагом 5 мм (ленточный вариант B). С 21.10.2026 PCB использует посадку `CP_Radial_D8.0mm_P5.00mm`, модель и отверстия совпадают. Габарит банки — 8×15 мм, к нему добавлен условный монтажный зазор 0,15 мм. Все сборочные допуски и высота после формовки выводов пока не подтверждены.

`RAD-DY-GF_3_ENVELOPE_ONLY_30x30x15.step` — только габаритный макет, без выдуманных направляющих, отверстий и рёбер. Он не установлен в сборку: рабочая ориентация, крепёж и изоляция радиаторов остаются открытыми. Эти модели служат для размещения; они не подтверждают механическую готовность платы.

Воспроизведение собственных моделей (CadQuery 2.7.0), обновление назначений и проверка:

```sh
python3 hardware/PCB_EU/tools/make_models3d.py
python3 hardware/PCB_EU/tools/models3d.py --write
python3 hardware/PCB_EU/tools/make_models3d.py --check
python3 hardware/PCB_EU/tools/models3d.py
```

`models3d.py` проверяет локальные пути, SHA-256, масштаб и преобразования; при записи отдельно доказывает сохранность всех не-3D данных PCB. Генераторы посадок и платы сохраняют назначения, включая отдельную модель C112. Источники и лицензии перечислены в [libraries/SOURCES.md](libraries/SOURCES.md), размеры/хеши и открытое расхождение — в [models3d.json](models3d.json). Стандартные модели KiCad пока имеют статус модели корпуса, без отдельной квалификации каждого MPN.
